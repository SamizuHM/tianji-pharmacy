# 药店门店智能问答 — 全流程演示指南

## 一、环境准备

### 1.1 启动依赖服务

```bash
# 首次初始化，准备 PostgreSQL/Qdrant、数据库、seed 和 ML Python 环境
pnpm dev:init

# 日常演示启动 Web + ML
pnpm dev
```

服务就绪确认：

- Qdrant: `curl http://127.0.0.1:6333/collections` → status: ok
- ML 服务: `curl http://127.0.0.1:8001/health` → status: ok
- Web: 浏览器访问 `http://127.0.0.1:3000` → 跳转到登录页

### 1.2 初始化数据

```bash
# 数据库迁移（首次或 schema 变更后）
npx prisma migrate dev

# 种子数据
pnpm db:seed

# 导入知识库（可选，首次演示建议执行）
pnpm kb:import
```

## 二、模块 A：智能问答（Staff 视角）

> 以「药店工作人员」登录

### A1. 登录

1. 打开 `http://127.0.0.1:3000`
2. 输入用户名 `药店工作人员`，密码 `demo123`
3. 点击「登录」→ 自动跳转到「问答工作台」

### A2. 知识库问答

1. 在输入框输入：`感冒药和退烧药能一起吃吗`
2. 点击发送，观察：
   - 进度条显示「检索知识库 → 匹配结果 → 生成回答」
   - 回答来源标签显示「知识库」
   - 回答末尾固定附带「如以上操作仍无法解决，建议您转人工进行咨询」
3. 点击回答下方的「有帮助 / 无帮助」按钮，提交反馈

### A3. 大模型兜底

1. 输入一个知识库中没有的问题：`门店空调坏了怎么办`
2. 观察：
   - 进度条显示「知识库未命中 → 大模型回答」
   - 回答来源标签显示「大模型」
   - 回答仍附带转人工提示

### A4. 多轮对话

1. 继续输入：`还有其他建议吗`
2. 观察系统保持上下文，理解"其他建议"指的是上一轮问题

### A5. 会话管理

1. 点击左上角「新建会话」按钮，创建新对话
2. 在左侧会话列表中切换不同会话
3. 鼠标悬停会话标题，点击删除图标可删除会话

### A6. 图片输入

1. 点击输入框左侧的「上传图片」按钮
2. 选择一张图片（药品照片等）
3. 输入文字：`这个药品怎么使用`
4. 观察系统结合图片和文字生成回答

## 三、模块 B：人工工单全流程

> 演示完整的工单生命周期：创建 → 认领 → 回复 → 转派 → 部门处理 → 提交方案 → 关闭

### B1. Staff 创建工单

1. 以「药店工作人员」登录，在问答工作台
2. 先提问一个实际问题：`医保刷卡失败了，显示错误代码E001，顾客很着急`
3. 等待 AI 回答后，点击右下角「转人工服务」按钮
4. 系统自动创建工单，弹出提示「工单已创建，等待部门人员认领」
5. 观察左侧导航「人工工单」出现红色待办计数

### B2. 部门人员查看并认领工单

1. **切换浏览器标签页**（或新开隐私窗口）
2. 以「医保办-陈静」登录 → 自动跳转到 `/department/tickets`（医保办工单台）
3. 观察页面：
   - 顶部显示「待认领 X，已转派 X」
   - Tab 栏「待认领」显示数字 1
   - 工单列表中出现刚才创建的工单
4. 点击工单的「查看详情」
5. 在工单详情页，点击右上角「认领工单」按钮
6. 观察工单状态从「待认领」变为「处理中」，当前处理人变为「陈静」

### B3. 部门人员回复工单

1. 在工单详情页的「继续处理」区域，输入回复：`已排查，医保网络正常，建议重启读卡器后重试`
2. 点击「发送处理回复」
3. 观察时间线出现新的回复卡片

### B4. 部门人员转派工单到部门

1. 在快速操作区域，点击「转派到部门」
2. 弹出部门树选择器，展示当前 seed 部门：
   - 营运部、采购部、培训部、人事部、财务部、医保办、技术服务部、其他部门
3. 点击「技术服务部」，可看到部门下的用户「孙鹏」
4. 可选择指定孙鹏或整个技术服务部
5. 点击确认，观察：
   - 工单状态变为「已转派」
   - 转派目标显示「技术服务部」
   - 当前处理人清空（等待部门专家认领）

### B5. 部门专家认领转派工单

1. **再开一个隐私窗口**，以「技术-孙鹏」登录
2. 自动跳转到 `/department/tickets`（技术服务部工单台）
3. 观察导航标题为「技术服务部工单台」，描述「处理转派到技术服务部的工单」
4. Tab 栏「已转派」显示数字 1
5. 点击工单详情，点击「认领工单」
6. 工单状态变为「处理中」，当前处理人变为「孙鹏」

### B6. 部门专家回复并提交解决方案

1. 回复：`已排查门店读卡器驱动和网络连通性，建议重启读卡器并重新登录医保结算模块后重试`
2. 在「提交解决方案」区域输入方案：
   ```
   问题原因：读卡器会话异常，医保结算模块未重新建立连接。
   解决方案：重启读卡器，重新登录医保结算模块，再发起刷卡。
   ```
3. 点击「提交解决方案」
4. 观察工单状态仍为「处理中」，但出现「方案提交人：孙鹏」

### B7. 并发认领冲突演示（可选）

1. 在管理员用户管理页临时创建另一个“其他部门”部门人员，或用第二个会话同时打开同一账号
2. 在两个窗口同时打开同一张待认领工单，分别点击「认领」
3. 系统返回 409 错误：`工单已被其他人认领`

### B8. Staff 确认问题已解决

1. 切回「药店工作人员」的浏览器窗口
2. 左侧导航点击「人工工单」，或直接访问 `/staff/tickets`
3. 找到该工单，点击「查看详情」
4. 观察右侧出现确认解决操作。
5. 点击确认问题已解决。
6. 观察：
   - 工单状态变为「已解决」
   - 系统消息提示部门人员可以整理待入库知识，等待生成草稿

### B9. 部门人员生成待入库知识并关闭工单

1. 切回当前处理部门人员账号。
2. 打开已解决工单详情。
3. 选择员工问题和人工回复作为材料。
4. 生成待入库知识草稿。
5. 观察工单的知识状态变为待写回。
6. 点击关闭工单。
7. 观察：
   - 工单状态变为「已关闭」
   - 关闭人显示当前处理部门人员
   - 系统消息「工单已关闭，人工生成的优质答案已写回知识库」
   - **知识库新增一条工单 QA 文档**

### B10. 工单消息录入知识库（独立功能）

1. 以部门人员身份打开任意未关闭工单
2. 在快速操作区点击「录入知识库」
3. 勾选工单中的用户问题消息和人工回复消息
4. 点击「确认选择（N 条）」
5. 自动在新标签页打开知识库管理页，问题/答案已预填
6. 补充业务分类和适用范围后可提交保存

## 四、模块 C：知识库管理

> 以任意角色登录，导航到「知识库管理」

### C1. 知识库概览

1. 点击左侧导航「知识库管理」
2. 观察顶部四个指标卡片：
   - 知识条目数：全量知识沉淀总量
   - 图片知识数：包含图片的知识条目
   - 今日新增：当天新增条目
   - 已发布：状态为 published、可被检索的条目

### C2. 知识导入

1. 在「知识入库」卡片中选择「导入文档」
2. 上传 Word、PDF、Markdown、TXT 或图片
3. 选择切片模式：通用文档、父子切片或 QA 文档
4. 点击「预览切片」，检查 chunk 内容
5. 点击「解析入库」
6. 导入记录显示任务状态，文档列表出现新文档

### C3. 手动新增知识

1. 在「知识入库」卡片中切换到「新增知识」：
   - 分类一：选择大类（如「医保政策」）
   - 分类二：选择小类（如「刷卡结算」）
   - 问题：输入「医保卡消磁了怎么处理」
   - 答案：输入详细解答内容
2. 点击「新增知识」
3. 观察「知识文档」列表新增一条 QA 文档

### C4. 知识检索与管理

1. 在知识文档表格中，使用搜索框搜索关键词、文档名或 chunk 内容
2. 使用分类筛选下拉框过滤特定分类
3. 点击「查看 chunk」打开文档详情
4. 检查 active chunk set 的切分内容、状态和切片策略

### C5. 知识重新索引

1. 对于已有但向量未同步的知识文档
2. 点击「重建索引」，以 PostgreSQL 中已发布且启用的 chunks 全量重建 Qdrant

> 点击左侧导航「统计分析」

### D1. 核心指标

1. 观察六个指标卡片：
   - 总提问数、知识库命中数、大模型回答数、转人工次数、工单总数、已关闭工单数

### D2. 趋势图表

1. 「近 7 天问答趋势」折线图：总提问数、知识库命中数、大模型回答数、转人工次数
2. 「知识库命中 vs 大模型兜底」环形图：展示命中率

### D3. 历史记录

1. 「历史问答」表格：展示用户提问内容、用户、回答方式、时间
2. 「历史工单」表格：展示工单编号、分类、优先级、状态、时间
3. 支持分页和搜索

## 六、模块 E：系统设置

> 点击左侧导航「系统设置」

### E1. 运行参数配置

1. 可调整的参数：
   - 检索返回数量（RETRIEVAL_TOP_K）
   - 重排序数量（RERANK_TOP_N）
   - 知识库命中阈值（KB_HIT_THRESHOLD）
   - 最大上下文轮数（MAX_CONTEXT_TURNS）
2. 修改后点击保存
