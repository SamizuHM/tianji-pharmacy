# 知识文档导入规范

## 功能定位

后台“上传 Word 文档并解析入库”用于把业务整理好的标准问答文档导入知识库。

它不是通用 Office 智能解析器，也不是任意文档总结工具。当前版本主要依赖规则解析，适合导入结构清晰、字段固定的 QA 文档。

底仓数据导入不在前端开放，统一由运维执行：

```bash
pnpm kb:import
```

## 支持范围

前端上传入口当前只支持：

1. `.docx`
2. `.doc`

其中 `.docx` 是推荐格式。`.doc` 需要运行环境安装 LibreOffice，系统会先尝试转换成 `.docx` 再解析；如果运行环境没有转换工具，导入会失败。

## 推荐模板

最稳定的格式是每条知识使用固定标签：

```text
一级分类：用药咨询
二级分类：感冒用药
具体问题：布洛芬混悬液儿童用法用量？
简要标准答案：1~3 岁，体重 10~15kg，每次 5ml；4~6 岁，体重 16~21kg，每次 7.5ml。
标签：儿童用药，退烧药
```

多条知识可以连续书写：

```text
一级分类：用药咨询
二级分类：感冒用药
具体问题：布洛芬混悬液儿童用法用量？
简要标准答案：按说明书或医嘱使用。
标签：儿童用药，退烧药

一级分类：用药咨询
二级分类：慢病用药
具体问题：二甲双胍缓释片饭前还是饭后服用？
简要标准答案：一般建议随餐或餐后服用，以降低胃肠道不适。
标签：糖尿病，用药时间
```

## 表格模板

也支持 Word 表格，但当前只稳定识别以下核心列：

```text
序号 | 具体问题 | 简要标准答案
```

示例：

```text
序号 | 具体问题 | 简要标准答案
1    | 布洛芬混悬液儿童用法用量？ | 按年龄、体重和说明书剂量使用。
2    | 二甲双胍缓释片饭前还是饭后服用？ | 一般建议随餐或餐后服用。
```

如果需要按表格维护分类，建议在表格前使用标题行：

```text
一、用药咨询
1.1 感冒用药
```

系统会把中文序号标题识别为一级分类，把 `1.1 xxx` 识别为二级分类。

## 图片规则

`.docx` 中的图片会被提取到 `uploads/knowledge-assets/...`，并尽量关联到对应 QA。

当前支持效果较好的图片位置：

1. 图片放在答案后面的独立段落。
2. 图片和问题/答案在同一个段落或同一个表格行里。
3. 图片在当前 QA 的“具体问题”到下一条 QA 之间。

不建议的图片用法：

1. 只放图片，没有任何问题或答案文字。
2. 图片使用复杂浮动版式、文本框、页眉页脚、批注、SmartArt。
3. 一张图片跨多个问题共用，但文档里没有明确说明归属。

## 兜底行为

如果文档没有明确的 QA 标签，也不是可识别的表格，系统会退化为“原文切片”：

```text
一级分类：知识文档
二级分类：原文切片
具体问题：文件名 - 第 N 段
简要标准答案：该段原文内容
```

这种方式可以入库，但检索质量不可控，不建议作为正式知识库维护方式。

## 不支持或不保证的情况

当前版本不保证以下文档能正确导入：

1. 扫描件、截图型 Word、图片型 PDF。
2. 没有“具体问题”和“简要标准答案”的长篇说明文。
3. 复杂嵌套表格、合并单元格严重的表格。
4. 文本框、页眉页脚、脚注、批注里的关键内容。
5. 同一条知识拆散在多个不连续位置。
6. 同一问题在同一来源文件中重复出现。

## 导入后的校验

导入后应在知识库列表中检查：

1. 问题是否被正确拆成独立知识条目。
2. 一级分类、二级分类是否正确。
3. 简要标准答案是否完整。
4. 图片是否显示在知识详情中。
5. 来源文件是否为上传的原始文件名。

如果导入结果不符合预期，应优先调整 Word 模板，而不是反复上传同一份非结构化文档。
