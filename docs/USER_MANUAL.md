# 用户操作手册

## 适用对象

本文面向实际使用系统的人员：

- 门店员工
- 部门人员
- 目标部门人员
- 需要维护知识库的使用者

本文不解释接口、不要求懂数据库，也不要求知道系统内部实现。所有步骤都按前端页面操作来写。

说明：知识库管理操作不对应独立账号；当前能访问 `/admin/knowledge` 的账号都可以进入知识库管理页。

---

## 系统能完成什么闭环

系统的核心目标是让门店问题逐步沉淀成知识库。

完整闭环如下：

```text
先有一条知识
  -> 门店员工提问
  -> 系统命中知识库并回答

遇到新问题
  -> 系统未命中知识库
  -> 门店员工转人工
  -> 部门人员看到一级工单
  -> 部门人员可以直接解决，或转派给目标部门人员
  -> 目标部门人员解决问题
  -> 目标部门人员整理待入库知识
  -> 门店员工确认问题已解决
  -> 部门人员关闭工单并写回知识库
  -> 系统把答案写回知识库
  -> 下次同类问题自动命中知识库
```

本文用一个示例问题贯穿说明：

```text
冷链冰箱 IoT 网关 COLD-X7 显示握手码 ZK-7788，
温度连续 30 分钟无法上传，门店应该怎么处理？
```

## 一、角色和入口

### 门店员工

门店员工主要负责提问、转人工、确认工单是否解决。

入口：

```text
员工问答页：/staff/chat
我的工单页：/staff/tickets
```

常用操作：

- 向智能助手提问。
- 查看历史会话。
- 上传图片。
- 将未解决的问题转人工。
- 查看人工回复。
- 确认问题是否已解决。

### 部门人员

部门人员主要负责处理门店提交的一级工单。

入口：

```text
工单处理页：/department/tickets
```

常用操作：

- 查看所有一级待认领工单。
- 认领工单。
- 回复门店员工。
- 直接提交解决方案。
- 将复杂问题转派给目标部门人员。

部门人员的关键规则：

```text
待认领工单对当前目标部门内的部门人员平等可见。
谁先认领，谁负责当前处理。
```

### 目标部门人员

目标部门人员主要负责处理被转派到自己部门或账号的专业问题。

入口：

```text
工单处理页：/department/tickets
```

常用操作：

- 查看转派到自己部门的工单。
- 认领转派工单。
- 回复专业处理方案。
- 提交解决方案。
- 整理待入库知识。

目标部门人员的关键规则：

```text
目标部门人员不直接处理普通一级待认领工单。
目标部门人员处理被转派到自己部门或账号的工单。
```

### 知识库管理页使用者

当前可进入知识库管理页的使用者，都可以维护标准问答。

入口：

```text
知识库管理页：/admin/knowledge
```

常用操作：

- 手动新增 QA 文档。
- 上传文档导入知识。
- 预览文档切片。
- 查看文档 chunk。
- 重建知识库索引。

### 系统设置页

当前可进入系统设置页的使用者，可以调整个人界面偏好。

入口：

```text
系统设置页：/admin/settings
```

常用操作：

- 选择侧边栏主题：蓝色经典或简约白色。
- 选择颜色模式：白天、夜间或跟随系统。

说明：

- 颜色模式会同时作用于蓝色经典和简约白色主题。
- “跟随系统”会按当前电脑或浏览器的明暗色偏好自动切换。
- 这些偏好按当前登录用户保存，不会影响其他用户。

## 二、先录入一条已知知识

本节说明“知识库已有答案时，门店提问如何直接命中”。

### 操作角色

可访问知识库管理页的使用者。

### 操作页面

进入：

```text
/admin/knowledge
```

### 操作步骤

1. 在「知识入库」卡片中切换到「新增知识」。
2. 填写业务分类：

   ```text
   医保
   ```

3. 选择适用范围：

   ```text
   通用
   ```

4. 填写具体问题：

   ```text
   银杏叶片慢病医保支付比例是多少？
   ```

5. 填写标准答案：

   ```text
   银杏叶片在本演示门店的慢病医保支付比例为70%。
   门店收银时应先确认顾客慢病备案有效，再选择慢病结算通道。
   如果系统提示目录匹配失败，应检查商品医保编码和慢病病种目录是否一致。
   ```

6. 确认状态为：

   ```text
   已发布
   ```

7. 点击保存。

### 页面预期

保存后，知识库列表中能看到这条知识。

如果页面有搜索框，可以搜索：

```text
银杏叶片
```

确认该知识存在。

## 三、门店员工提问并命中知识库

### 操作角色

门店员工。

### 操作页面

进入：

```text
/staff/chat
```

### 操作步骤

1. 在底部输入框中输入：

   ```text
   银杏叶片慢病医保支付比例是多少？
   ```

2. 点击发送。

3. 等待智能助手回复。

### 页面预期

智能助手应返回类似内容：

```text
银杏叶片慢病医保支付比例为70%。
收银时请先确认顾客慢病备案有效，再选择慢病结算通道。
如果目录匹配失败，请检查商品医保编码和慢病病种目录是否一致。
```

这说明：

```text
知识库已有答案
  -> 员工提问
  -> 系统直接使用知识库回答
```

### 门店员工下一步

如果答案解决问题，不需要转人工。

如果答案仍无法解决，可以继续追问或转人工。

## 四、聊天消息的常用操作

### 复制和下载

每条聊天消息旁边有操作按钮。

常用操作：

- 复制 Markdown。
- 复制纯文本。
- 下载 Markdown。
- 下载纯文本。

说明：

- 助手回答支持 Markdown 展示，表格、列表、代码块会按格式显示。
- 复制纯文本时会自动去掉 Markdown 标记，适合粘贴到普通工单或即时通讯工具。

### 编辑消息

如果问题中有错别字、型号、报错码写错，可以编辑消息。

操作步骤：

1. 找到要修改的消息。
2. 点击编辑按钮。
3. 修改文字后点击保存。

注意：

- 正在生成中的消息不能编辑。
- 仅保存编辑只会改变当前消息内容，不会自动重新生成后续 AI 回答。

### 编辑后重新发送

如果修改的是门店员工发出的用户问题，并且希望 AI 按新问题重新回答，应点击：

```text
重新发送
```

系统会：

```text
更新这条用户消息
  -> 删除它之后的旧消息
  -> 重新检索知识库
  -> 重新生成助手回答
```

这适合“原问题写错，需要从该处重新开始”的场景。

### 重新生成助手回答

如果用户问题没有错，但想让系统基于同一问题重新回答，可以对助手消息点击重新生成。

系统会复用原助手消息位置，不会额外插入一条重复回答。

### 删除消息

如果某条消息不应保留，可以删除。

注意：

- 正在生成中的消息不能删除。
- 删除单条消息不会删除整个会话。
- 如果要删除整个历史会话，应使用会话列表里的删除按钮。

## 五、门店员工提出一个知识库没有的新问题

### 操作角色

门店员工。

### 操作页面

进入：

```text
/staff/chat
```

### 操作步骤

1. 点击新建会话，或直接在当前新会话界面输入问题。
2. 输入：

   ```text
   冷链冰箱 IoT 网关 COLD-X7 显示握手码 ZK-7788，
   温度连续 30 分钟无法上传，门店应该怎么处理？
   ```

3. 点击发送。

### 页面预期

由于知识库暂时没有这条标准知识，智能助手会给出一个大模型兜底回答。

页面上通常会出现类似提示：

```text
如以上操作仍无法解决，建议您转人工进行咨询
```

### 门店员工判断

如果门店员工认为 AI 回答不够准确，或仍无法解决现场问题，应点击：

```text
转人工
```

## 六、门店员工转人工

### 操作角色

门店员工。

### 操作页面

仍在：

```text
/staff/chat
```

### 操作步骤

1. 在当前会话中点击转人工按钮。
2. 系统创建工单。
3. 页面提示工单已创建，或跳转/引导到工单页面。

### 页面预期

员工可以进入：

```text
/staff/tickets
```

看到自己刚提交的工单。

工单状态通常显示为：

```text
待认领
```

这表示工单已进入部门人员公共待处理池。

---

## 七、部门人员查看一级待认领工单

### 操作角色

部门人员。

例如：

```text
营运-张伟
采购-李娜
技术-孙鹏
```

### 操作页面

进入：

```text
/department/tickets
```

### 操作步骤

1. 打开工单处理页。
2. 切换到待认领或一级待处理列表。
3. 查找标题中包含：

   ```text
   COLD-X7
   ZK-7788
   ```

### 页面预期

只有工单当前分发或转派到的目标部门人员能看到这张待认领工单。

例如：

```text
如果工单当前处理部门是技术服务部：
技术-孙鹏 能看到
营运-张伟 和 采购-李娜 看不到
```

这体现了一级工单的规则：

```text
待认领工单不是提前分配给某一个具体人员。
同一目标部门内的部门人员平等可见。
```

## 八、部门人员认领工单

### 操作角色

部门人员。

### 操作页面

进入：

```text
/department/tickets
```

打开该工单详情。

### 操作步骤

1. 点击工单。
2. 查看员工问题和 AI 初始回答。
3. 点击：

   ```text
   认领
   ```

### 页面预期

工单状态从：

```text
待认领
```

变成：

```text
处理中
```

工单详情中会出现系统消息：

```text
营运-张伟 已认领工单
```

认领后，当前部门人员成为该工单的处理人。

---

## 九、部门人员的两种处理方式

部门人员认领后有两种选择。

### 方式 A：部门人员直接解决

如果部门人员知道答案，可以直接：

1. 在回复框中填写处理建议。
2. 点击发送回复。
3. 填写处理方案。
4. 点击提交处理方案。
5. 等门店员工确认问题已解决。
6. 选择员工问题和部门人员答案，生成待入库知识并关闭工单。

这种情况下不需要转派目标部门人员。

### 方式 B：转派目标部门人员

如果问题需要专业部门处理，则转派。

本案例采用这种方式。

   ```text

   ```

```text

营运-张伟 已将工单转派至营运部。
```

## 十二、目标部门人员回复处理建议

### 操作角色

目标部门人员。

### 操作页面

工单详情页。

### 操作步骤

在回复框中输入专业处理建议：

```text
营运部排查结论：
COLD-X7 出现 ZK-7788 时，先确认网关电源和门店网络正常；
长按网关复位键 8 秒重启，等待指示灯由红闪变为绿闪；
随后在冷链平台重新绑定设备编号并点击手动上传。
若 10 分钟内仍未恢复，记录网关 SN、冰箱编号和最近一次温度截图，
提交营运部设备工单更换网关。
```

点击发送。

### 页面预期

工单对话区出现专家回复。

门店员工回到自己的工单详情时，也能看到这条回复。

---

## 十三、目标部门人员提交处理方案

### 操作角色

目标部门人员。

### 操作页面

工单详情页。

### 操作步骤

在处理方案区域填写：

```text
COLD-X7 网关 ZK-7788 为设备握手失败。
处理步骤：
1. 检查网关电源和门店网络；
2. 长按复位键 8 秒重启；
3. 指示灯变绿闪后在冷链平台重新绑定设备编号；
4. 点击手动上传温度；
5. 10 分钟仍失败时，带网关 SN、冰箱编号和温度截图提交营运部设备工单更换网关。
```

点击：

```text
提交处理方案
```

### 页面预期

页面提示处理方案已提交。

工单详情中出现系统消息：

```text
处理方案已提交，等待药店工作人员确认关闭。
```

注意：

```text
目标部门人员提交方案后，工单还没有关闭。
当前系统消息中的“确认关闭”表示门店员工确认问题已解决。
真正关闭工单和写回知识库由部门人员后续完成。
```

## 十四、目标部门人员生成待入库知识

### 操作角色

目标部门人员。

### 操作页面

工单详情页的知识沉淀区域。

### 操作步骤

1. 找到知识沉淀或生成入库内容区域。
2. 在可选材料中勾选：

   ```text
   门店员工原始问题
   目标部门人员专业回答
   ```

3. 点击：

   ```text
   生成待入库内容
   ```

4. 查看系统生成的知识草稿。

### 页面预期

系统生成类似内容：

```text
业务分类：-
适用范围：通用

问题：
冷链冰箱 IoT 网关 COLD-X7 显示握手码 ZK-7788 且温度无法上传时，门店应如何处理？

答案：
1. 确认网关电源连接正常，且门店网络通畅。
2. 长按网关复位键 8 秒进行重启，等待指示灯由红闪变为绿闪。
3. 登录冷链平台，重新绑定设备编号并点击手动上传。
4. 若 10 分钟内仍未恢复，请记录网关 SN、冰箱编号及最近一次温度截图，提交营运部设备工单申请更换网关。
```

### 重要说明

此时只是生成“待入库知识”。

它还没有正式进入知识库。

正式写入知识库发生在：

```text
工单已确认解决后，部门人员关闭工单时
```

## 十五、门店员工确认问题已解决

### 操作角色

门店员工。

### 操作页面

进入：

```text
/staff/tickets
```

打开该工单详情。

### 操作步骤

1. 查看目标部门人员回复。
2. 确认问题已经解决。
3. 点击：

   ```text
   确认问题已解决
   ```

4. 根据页面提示确认。

### 页面预期

工单状态变为：

```text
已解决
```

工单对话区出现系统消息：

```text
药店工作人员已确认问题解决，部门人员可以整理待入库知识。
```

### 业务含义

门店员工确认解决，表示：

```text
这个处理方案确实解决了门店问题。
```

确认解决后，部门人员才能整理并生成待入库知识。

## 十六、部门人员关闭工单并写回知识库

### 操作角色

当前处理部门人员，或提交工单的门店员工。

### 操作页面

部门人员进入：

```text
/department/tickets
```

打开已解决工单详情。

### 操作步骤

1. 选择用于入库的用户问题和有效回答。
2. 生成待入库知识草稿。
3. 检查问题、答案、分类和标签。
4. 点击关闭工单。

### 页面预期

工单状态变为：

```text
已关闭
```

知识状态变为：

```text
已写入
```

工单对话区出现系统消息：

```text
工单已关闭，人工生成的优质答案已写回知识库。
```

### 业务含义

关闭工单表示人工处理闭环完成，并把已确认有效的解决方案正式写入知识库。

## 十七、门店员工再次提问并命中知识库

### 操作角色

门店员工。

### 操作页面

进入：

```text
/staff/chat
```

### 操作步骤

重新提问：

```text
COLD-X7 显示 ZK-7788 后温度上传失败怎么处理？
```

点击发送。

### 页面预期

这一次，系统应直接使用知识库回答。

答案应包含：

```text
检查网关电源和门店网络。
长按复位键 8 秒重启。
在冷链平台重新绑定设备编号并手动上传。
10 分钟仍未恢复时，记录网关 SN、冰箱编号和温度截图，提交营运部设备工单更换网关。
```

这说明闭环完成：

```text
新问题
  -> 人工解决
  -> 知识沉淀
  -> 员工确认
  -> 写回知识库
  -> 后续自动命中
```

## 十九、常见操作问题

### 为什么同一部门人员都能看到同一张待认领工单？

因为待认领工单进入的是目标部门的公共待认领池。

系统希望同一目标部门内的部门人员可以平等抢单处理。

### 部门人员认领后，其他部门人员还能处理吗？

通常不能直接作为当前处理人继续处理。

认领后，工单进入处理中，当前认领人成为负责人。

### 部门人员一定要转派吗？

不一定。

如果部门人员能解决，可以直接回复、提交处理方案，等门店员工确认问题已解决后，再生成待入库知识并关闭工单。

### 目标部门人员为什么看不到所有一级待认领工单？

目标部门人员处理的是专业流转问题。

普通一级问题先由部门人员判断和处理。

### 专家提交处理方案后，为什么工单没有自动关闭？

因为最终是否解决，应由提出问题的门店员工确认。

### 生成待入库知识后，为什么还不能立即在知识库中看到？

因为它只是草稿。

只有工单已确认解决，并在关闭时完成写回后，系统才正式把草稿写入知识库。

### 关闭工单失败怎么办？

常见原因：

1. 部门人员还没有提交处理方案。
2. 门店员工还没有确认问题已解决。
3. 部门人员还没有生成待入库知识。
4. 当前登录用户不是提交该工单的门店员工，也不是当前处理部门人员。

处理方式：

- 请部门人员先提交处理方案。
- 请提交工单的门店员工先确认问题已解决。
- 请部门人员先生成待入库知识。
- 使用提交工单的员工账号或当前处理部门人员账号关闭。

### 再次提问没有命中知识库怎么办？

可以检查：

1. 工单是否已经关闭。
2. 工单知识状态是否为已写入。
3. 知识库管理页的「知识文档」列表是否能搜到该 QA 文档。
4. 是否需要重建索引。

如果知识文档中能看到知识，但问答不命中，可以由能访问知识库管理页的使用者在后台执行重建索引。

## 二十、操作建议

### 门店员工

- 问题描述尽量写清楚设备型号、报错码、发生场景。
- 如果有截图，可以上传图片。
- AI 回答无法解决时及时转人工。
- 人工给出方案后，确认有效再关闭工单。

### 部门人员

- 先判断问题是否属于常见门店操作问题。
- 能解决就直接回复和提交方案。
- 不能解决时转派到正确部门。
- 转派前尽量补充判断依据，方便目标部门人员接手。

### 目标部门人员

- 回复内容尽量写成门店能执行的步骤。
- 提交处理方案时避免只写“已处理”。
- 生成待入库知识时，优先选择“员工原始问题”和“最终有效答案”。
- 知识问题应概括场景，答案应包含可执行步骤。

### 知识库管理页使用者

- 定期检查工单写回的知识。
- 合并重复知识。
- 修正分类和标签。
- 对重要知识执行检索验证。
