# 用户操作手册

## 适用对象

本文面向实际使用系统的人员：

- 门店员工
- 一线客服
- 二级专家
- 需要维护知识库的使用者

本文不解释接口、不要求懂数据库，也不要求知道系统内部实现。所有步骤都按前端页面操作来写。

说明：知识库管理操作不对应独立账号；当前能访问 `/admin/knowledge` 的账号都可以进入知识库管理页。

---

## 系统能完成什么闭环

系统的核心目标是让门店问题逐步沉淀成知识库。

完整闭环如下：

```text
先有一条知识
  -> 门店员工提问
  -> 系统命中知识库并回答

遇到新问题
  -> 系统未命中知识库
  -> 门店员工转人工
  -> 一线客服看到一级工单
  -> 一线客服可以直接解决，或升级给二级专家
  -> 二级专家解决问题
  -> 二级专家整理待入库知识
  -> 门店员工确认关闭工单
  -> 系统把答案写回知识库
  -> 下次同类问题自动命中知识库
```

本文用一个示例问题贯穿说明：

```text
冷链冰箱 IoT 网关 COLD-X7 显示握手码 ZK-7788，
温度连续 30 分钟无法上传，门店应该怎么处理？
```

## 一、角色和入口

### 门店员工

门店员工主要负责提问、转人工、确认工单是否解决。

入口：

```text
员工问答页：/staff/chat
我的工单页：/staff/tickets
```

常用操作：

- 向智能助手提问。
- 查看历史会话。
- 上传图片。
- 将未解决的问题转人工。
- 查看人工回复。
- 确认关闭工单。

### 一线客服

一线客服主要负责处理门店提交的一级工单。

入口：

```text
工单处理页：/agent/tickets
```

常用操作：

- 查看所有一级待认领工单。
- 认领工单。
- 回复门店员工。
- 直接提交解决方案。
- 将复杂问题升级给二级专家。

一线客服的关键规则：

```text
一级待认领工单对所有一线客服平等可见。
谁先认领，谁负责当前处理。
```

### 二级专家

二级专家主要负责处理被升级到自己部门或账号的专业问题。

入口：

```text
工单处理页：/agent/tickets
```

常用操作：

- 查看升级到自己部门的工单。
- 认领升级工单。
- 回复专业处理方案。
- 提交解决方案。
- 整理待入库知识。

二级专家的关键规则：

```text
二级专家不直接处理普通一级待认领工单。
二级专家处理被升级到自己部门或账号的工单。
```

### 知识库管理页使用者

当前可进入知识库管理页的使用者，都可以维护标准问答。

入口：

```text
知识库管理页：/admin/knowledge
```

常用操作：

- 新增知识。
- 编辑知识。
- 删除或归档知识。
- 上传文档导入知识。
- 重建知识库索引。

## 二、先录入一条已知知识

本节说明“知识库已有答案时，门店提问如何直接命中”。

### 操作角色

可访问知识库管理页的使用者。

### 操作页面

进入：

```text
/admin/knowledge
```

### 操作步骤

1. 点击知识库页面的新增按钮。
2. 填写一级分类：

   ```text
   医保结算
   ```

3. 填写二级分类：

   ```text
   慢病支付
   ```

4. 填写具体问题：

   ```text
   银杏叶片慢病医保支付比例是多少？
   ```

5. 填写标准答案：

   ```text
   银杏叶片在本演示门店的慢病医保支付比例为70%。
   门店收银时应先确认顾客慢病备案有效，再选择慢病结算通道。
   如果系统提示目录匹配失败，应检查商品医保编码和慢病病种目录是否一致。
   ```

6. 确认状态为：

   ```text
   已发布
   ```

7. 点击保存。

### 页面预期

保存后，知识库列表中能看到这条知识。

如果页面有搜索框，可以搜索：

```text
银杏叶片
```

确认该知识存在。

## 三、门店员工提问并命中知识库

### 操作角色

门店员工。

### 操作页面

进入：

```text
/staff/chat
```

### 操作步骤

1. 在底部输入框中输入：

   ```text
   银杏叶片慢病医保支付比例是多少？
   ```

2. 点击发送。

3. 等待智能助手回复。

### 页面预期

智能助手应返回类似内容：

```text
银杏叶片慢病医保支付比例为70%。
收银时请先确认顾客慢病备案有效，再选择慢病结算通道。
如果目录匹配失败，请检查商品医保编码和慢病病种目录是否一致。
```

这说明：

```text
知识库已有答案
  -> 员工提问
  -> 系统直接使用知识库回答
```

### 门店员工下一步

如果答案解决问题，不需要转人工。

如果答案仍无法解决，可以继续追问或转人工。

## 四、门店员工提出一个知识库没有的新问题

### 操作角色

门店员工。

### 操作页面

进入：

```text
/staff/chat
```

### 操作步骤

1. 点击新建会话，或直接在当前新会话界面输入问题。
2. 输入：

   ```text
   冷链冰箱 IoT 网关 COLD-X7 显示握手码 ZK-7788，
   温度连续 30 分钟无法上传，门店应该怎么处理？
   ```

3. 点击发送。

### 页面预期

由于知识库暂时没有这条标准知识，智能助手会给出一个大模型兜底回答。

页面上通常会出现类似提示：

```text
如以上操作仍无法解决，建议您转人工进行咨询
```

### 门店员工判断

如果门店员工认为 AI 回答不够准确，或仍无法解决现场问题，应点击：

```text
转人工
```

## 五、门店员工转人工

### 操作角色

门店员工。

### 操作页面

仍在：

```text
/staff/chat
```

### 操作步骤

1. 在当前会话中点击转人工按钮。
2. 系统创建工单。
3. 页面提示工单已创建，或跳转/引导到工单页面。

### 页面预期

员工可以进入：

```text
/staff/tickets
```

看到自己刚提交的工单。

工单状态通常显示为：

```text
待认领
```

这表示工单已进入一线客服公共待处理池。

## 六、一线客服查看一级待认领工单

### 操作角色

一线客服。

例如：

```text
人工处理1
人工处理2
人工处理3
```

### 操作页面

进入：

```text
/agent/tickets
```

### 操作步骤

1. 打开工单处理页。
2. 切换到待认领或一级待处理列表。
3. 查找标题中包含：

   ```text
   COLD-X7
   ZK-7788
   ```

### 页面预期

所有一线客服都能看到这张一级待认领工单。

例如：

```text
人工处理1 能看到
人工处理2 也能看到
人工处理3 也能看到
```

这体现了一级工单的规则：

```text
一级工单不是提前分配给某一个客服。
所有一线客服平等可见。
```

## 七、一线客服认领工单

### 操作角色

一线客服。

### 操作页面

进入：

```text
/agent/tickets
```

打开该工单详情。

### 操作步骤

1. 点击工单。
2. 查看员工问题和 AI 初始回答。
3. 点击：

   ```text
   认领
   ```

### 页面预期

工单状态从：

```text
待认领
```

变成：

```text
处理中
```

工单详情中会出现系统消息：

```text
人工处理1 已认领工单
```

认领后，当前一线客服成为该工单的处理人。

---

## 八、一线客服的两种处理方式

一线客服认领后有两种选择。

### 方式 A：一线客服直接解决

如果一线客服知道答案，可以直接：

1. 在回复框中填写处理建议。
2. 点击发送回复。
3. 填写处理方案。
4. 点击提交处理方案。
5. 选择员工问题和客服答案，生成待入库知识。
6. 等门店员工确认关闭。

这种情况下不需要升级二级专家。

### 方式 B：升级二级专家

如果问题需要专业部门处理，则升级。

本案例采用这种方式。

## 十二、二级专家提交处理方案

### 操作角色

二级专家。

### 操作页面

工单详情页。

### 操作步骤

在处理方案区域填写：

```text
COLD-X7 网关 ZK-7788 为设备握手失败。
处理步骤：
1. 检查网关电源和门店网络；
2. 长按复位键 8 秒重启；
3. 指示灯变绿闪后在冷链平台重新绑定设备编号；

```

```text
处理方案已提交，等待药店工作人员确认关闭。
```

注意：

```text
二级专家提交方案后，工单还没有关闭。
最终关闭需要门店员工确认。
```

## 十三、二级专家生成待入库知识

### 操作角色

二级专家。

### 操作页面

工单详情页的知识沉淀区域。

### 操作步骤

1. 找到知识沉淀或生成入库内容区域。
2. 在可选材料中勾选：

   ```text
   门店员工原始问题
   二级专家专业回答
   ```

3. 点击：

   ```text
   生成待入库内容
   ```

4. 查看系统生成的知识草稿。

### 页面预期

系统生成类似内容：

```text
一级分类：设备运维
二级分类：冷链监控

问题：
冷链冰箱 IoT 网关 COLD-X7 显示握手码 ZK-7788 且温度无法上传时，门店应如何处理？

答案：
1. 确认网关电源连接正常，且门店网络通畅。
2. 长按网关复位键 8 秒进行重启，等待指示灯由红闪变为绿闪。
3. 登录冷链平台，重新绑定设备编号并点击手动上传。
4. 若 10 分钟内仍未恢复，请记录网关 SN、冰箱编号及最近一次温度截图，提交营运部设备工单申请更换网关。
```

### 重要说明

此时只是生成“待入库知识”。

它还没有正式进入知识库。

正式写入知识库发生在：

```text
门店员工确认关闭工单时
```

## 十七、常见操作问题

### 为什么一线客服都能看到同一张待认领工单？

因为一级工单进入的是公共待认领池。

系统希望一线客服可以平等抢单处理。

### 一线客服认领后，其他一线客服还能处理吗？

通常不能直接作为当前处理人继续处理。

认领后，工单进入处理中，当前认领人成为负责人。

### 一线客服一定要升级吗？

不一定。

如果一线客服能解决，可以直接回复、提交处理方案、生成待入库知识。

### 二级专家为什么看不到所有一级待认领工单？

二级专家处理的是专业升级问题。

普通一级问题先由一线客服判断和处理。

### 专家提交处理方案后，为什么工单没有自动关闭？

因为最终是否解决，应由提出问题的门店员工确认。

### 生成待入库知识后，为什么还不能立即在知识库中看到？

因为它只是草稿。

只有门店员工确认关闭工单后，系统才正式写回知识库。

### 员工关闭工单失败怎么办？

常见原因：

1. 客服或专家还没有提交处理方案。
2. 客服或专家还没有生成待入库知识。
3. 当前登录用户不是提交该工单的门店员工。

处理方式：

- 请客服或专家先提交处理方案。
- 请客服或专家先生成待入库知识。
- 使用提交工单的员工账号关闭。

### 再次提问没有命中知识库怎么办？

可以检查：

1. 工单是否已经关闭。
2. 工单知识状态是否为已写入。
3. 知识库管理页是否能搜到该知识。
4. 是否需要重建索引。

如果知识库中能看到知识，但问答不命中，可以由能访问知识库管理页的使用者在后台执行重建索引。

## 十八、操作建议

### 门店员工

- 问题描述尽量写清楚设备型号、报错码、发生场景。
- 如果有截图，可以上传图片。
- AI 回答无法解决时及时转人工。
- 人工给出方案后，确认有效再关闭工单。

### 一线客服

- 先判断问题是否属于常见门店操作问题。
- 能解决就直接回复和提交方案。
- 不能解决时升级到正确部门。
- 升级前尽量补充判断依据，方便二级专家接手。

### 二级专家

- 回复内容尽量写成门店能执行的步骤。
- 提交处理方案时避免只写“已处理”。
- 生成待入库知识时，优先选择“员工原始问题”和“最终有效答案”。
- 知识问题应概括场景，答案应包含可执行步骤。

### 知识库管理页使用者

- 定期检查工单写回的知识。
- 合并重复知识。
- 修正分类和标签。
- 对重要知识执行检索验证。
